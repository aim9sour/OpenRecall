# OpenRecall

[English](README.md)

OpenRecall تطبيق ويب محلي للمراجعة المتباعدة، مصمم أولًا للوحة المفاتيح
وللاستخدام مع Chrome وNVDA. يحتفظ بالأقسام والبطاقات وسجل المراجعة
والإحصاءات والإعدادات والنسخ الاحتياطية على الجهاز نفسه. لا يستمع الخادم إلا
على `http://127.0.0.1:3210`، ولا توجد حسابات أو مزامنة سحابية أو قياسات
استخدام أو اعتماد خارجي وقت التشغيل.

> حالة النشر: لا يوجد ترخيص مفتوح المصدر لهذا المستودع حاليًا. اقرأ
> [قرار الترخيص](docs/decisions/licensing.md) قبل النسخ أو التوزيع أو النشر.

## ما الذي توفره المنصة؟

- واجهتان عربية وإنجليزية قابلتان للوصول، واتجاها RTL وLTR، وسمات مرئية،
  وألوان قسرية، وتقليل الحركة، وغلاف PWA قابل للتثبيت.
- أقسام وبطاقات وإحصاءات عامة وتفصيلية، وتعديل ونقل إلى السلة واستعادة وحذف،
  واستيراد JSON بنص صريح.
- حالة جدولة واحدة لكل مادة تعليمية مع أي عدد من الصيغ البديلة. يدوّر النظام
  الصياغات بذكاء من غير اعتبارها بطاقات منفصلة.
- طابور مستمر: تدخل البطاقة إلى الجلسة عندما يحين موعدها فعلًا، بلا خطوات
  استطلاع ثابتة كل عشر دقائق.
- التقييمات الأربعة: Again وHard وGood وEasy من خلال محول FSRS ذي نسخة
  معلومة.
- إعدادات عامة، وتجاوزات لكل قسم، وتدريب المعاملات، ومعاينة ملفات المعاملات
  وتطبيقها والتراجع عنها مع بدائل آمنة.
- النسخ الاحتياطي والاستعادة بملفات SQLite فقط. JSON لتبادل البطاقات وليس
  نسخة احتياطية.

## المتطلبات

- Node.js 24.18 أو أحدث داخل سلسلة Node 24.
- pnpm 11.17.0.
- Chrome، وNVDA هو قارئ الشاشة الأساسي لاختبارات القبول على Windows.

للتفاصيل راجع
[تشغيل OpenRecall على Windows](docs/getting-started/windows-ar.md).

## التثبيت والتشغيل

من جذر المستودع:

```bash
pnpm install --frozen-lockfile
pnpm build
pnpm start
```

انتظر ظهور `OPENRECALL_READY` ثم افتح
`http://127.0.0.1:3210` في Chrome. على Windows يمكنك تشغيل
`scripts\start-openrecall.cmd`. أوقف الخادم بـ`Ctrl+C` وانتظر عودة سطر
الأوامر حتى تكتمل الطلبات الجارية وتغلق SQLite بأمان.

للتطوير:

```bash
pnpm dev
```

تعمل واجهة التطوير على `http://127.0.0.1:5173` وتظل واجهة API مقيدة بالخادم
المحلي.

## عقد الإتاحة مع Chrome وNVDA

كل وظيفة قابلة للاستخدام بلوحة المفاتيح. عند ظهور بطاقة ينتقل التركيز إلى
عنوان السؤال، وعند العرض إلى محتوى الإجابة، وبعد التقييم إلى السؤال التالي
مباشرة. لا يضيف الاسم القابل للوصول كلمة «سؤال» أو «إجابة» قبل نص البطاقة،
وتظل الملاحظات عنوانًا يمكن الوصول إليه من غير فرض نطق اسم العنوان قبل
الإجابة. إعلانات حالة الطابور والجلسة قصيرة ولا تكرر محتوى البطاقة الخاص.

اختبارات axe الآلية ضرورية لكنها غير كافية؛ أي تغيير في المسارات الأساسية
يتطلب اختبارًا يدويًا بآخر نسخة مستقرة من Chrome وNVDA بالعربية والإنجليزية.

## استيراد البطاقات من JSON

ابدأ من [المثال الصحيح](examples/cards.valid.json)، واقرأ
[صيغة الاستيراد الكاملة](docs/import/format.md). الحقلان `front` و`back`
إلزاميان كنص صريح، أما `notes` و`variants` فاختياريان. كل الصيغ البديلة
تشترك في حالة الجدولة الخاصة بالمادة الأصلية. تعرض المنصة معاينة ومسارات
الأخطاء بدقة، ثم تحفظ الصفوف الصحيحة التي تختارها فقط.

## المجدول والمحسن

الخط الأساسي الحالي هو **FSRS-6** عبر `ts-fsrs@5.4.1`، وله 21 معاملًا
ومحول ذو نسخة محفوظة. يستخدم المحسن
`@open-spaced-repetition/binding@0.5.0`. ‏FSRS-7 غير مدعوم حاليًا؛ البنية
مجهزة لإضافة محول مستقبلي عندما يتوفر تنفيذ upstream مستقر، ولا تدعي المنصة
تشغيله أو محاكاته. راجع
[بروتوكول ترقية المجدول](docs/architecture/scheduler-upgrades.md).

## الخصوصية والبيانات والنسخ الاحتياطي

كل حركة التطبيق محلية ومن نفس الأصل. تمنع اختبارات أمان الإنتاج اتصالات DNS
والشبكة الخارجة. لا يخزن PWA ردود API أو نصوص البطاقات في مخزنه التشغيلي،
وتحتوي السجلات على أكواد ثابتة وتوقيتات لا على محتوى البطاقات.

المجلد الافتراضي على Windows هو
`%LOCALAPPDATA%\OpenRecall-nodejs\Data`. قاعدة البيانات الحية هي
`openrecall.sqlite3`، واللقطات المتحققة داخل `backups`، والتشخيصات الخالية
من المحتوى داخل `logs`. نزّل نسخة SQLite من الإعدادات قبل التغييرات الخطرة،
ولا تنسخ ملف القاعدة الحية وحده أثناء عمل الخادم.

## حدود الإصدار الأول

لا توجد حسابات أو استضافة بعيدة أو مزامنة سحابية أو تعاون أو استيراد حزم
Anki أو تطبيق أصلي للهاتف أو سطح المكتب. الصور والصوت والفيديو وHTML وMarkdown
وLaTeX والمحتوى التنفيذي غير مدعومة عمدًا. جدولة FSRS-7 التجريبية خارج حدود
الإصدار الأول أيضًا.

# OpenRecall 1.1.0

OpenRecall 1.1.0 is a stable feature and maintenance release for the local-only,
keyboard-first spaced-repetition application. It adds the complete safe
optimizer-settings surface and official learning-step recommendations, improves
review and import behavior, and refreshes the verified Windows runtime bundle.

## Highlights

- Configure supported optimizer training controls globally or per section.
- Analyze learning and relearning history with the official optimizer, preview
  its recommendation, apply it deliberately, and restore the previous steps.
- Keep section pages compact with statistics, cards, and management collapsed
  until requested.
- See primary notes while deciding which cards to import.
- Receive cards at their actual due time during an active review, immediately
  after the card already on screen.

## Learning-step recommendations

The new recommendation panel uses the official
`@open-spaced-repetition/binding@0.5.0` implementation. Before a run it reports
the eligible and excluded review counts for the chosen global or section scope.
Analysis runs outside the server request thread, can be cancelled, and survives
ordinary page navigation through its persisted run record.

Results show the exact upstream durations—including seconds—beside the minute
values OpenRecall can store. Applying a result requires an explicit preview.
Restore returns the affected settings to their pre-application values. A
fingerprint prevents an old result from being applied after relevant history,
settings, a database restore, or section state has changed.

## Advanced optimizer settings

Settings now expose the upstream controls that are both officially supported
and reasonable for a power user to change. Each control has a localized
description, native bounds, strict validation, and a reset path. Operational or
compatibility failures in this panel do not disable language, scheduler,
backup, or restore settings.

Per-section training settings are used when that section has enough retained
history. Otherwise OpenRecall clearly falls back to the global settings. The
native binding version, schema, and supported option inventory are checked at
the adapter boundary so a future upstream upgrade fails closed instead of
silently changing behavior.

## Review and import improvements

- A learning card that becomes due during the session is inserted immediately
  after the active card rather than at the end of the original backlog.
- **End review** now completes the session immediately. It no longer opens a
  pause-or-finish choice.
- Import preview shows the primary optional notes with the front and back. Notes
  and variants remain optional; front and back remain required.
- Section statistics, cards, and management disclosures are collapsed by
  default and load their heavier content only when opened.

## Accessibility and localization

Optimizer status and conflicts use short, isolated live announcements instead
of competing status regions. Delayed responses are tied to the scope that
started them, so fast global/section navigation cannot announce or display an
older scope. Exact durations, errors, help text, and new controls are available
through the Arabic, English, and translation-test catalogs.

Chrome with NVDA remains the primary Windows acceptance target. Card content is
ordinary text beneath navigable label headings, automatic review focus speaks
the content itself, and OpenRecall never changes NVDA or its settings.

## Installation and portable mode

Download `OpenRecall-v1.1.0-windows-x64.zip` from the
[latest GitHub release](https://github.com/aim9sour/OpenRecall/releases/latest),
extract the entire archive to a writable folder, then double-click:

- `OpenRecall.cmd` for normal data in
  `%LOCALAPPDATA%\OpenRecall-nodejs\Data`.
- `OpenRecall-Portable.cmd` for data in `Data` beside the launcher.

The ZIP includes the verified Node.js 24.18.0 runtime. It needs no separate
Node.js, pnpm, installer, administrator access, account, or cloud service. Both
launchers wait for the loopback server to become healthy before opening the
Windows default browser.

## Updating and SQLite safety

Create and download a SQLite backup from Settings before updating. Stop the old
launcher with `Ctrl+C` and wait for clean shutdown before replacing files. For
portable mode, keep the existing `Data` folder when moving to the new extracted
application; normal-mode data remains in Local App Data.

On first start, an older supported OpenRecall database is migrated in place only
after OpenRecall creates and validates an automatic pre-migration SQLite
snapshot. The new migrations add optimizer-training settings and persisted step
recommendation runs. Do not open the upgraded database with an older OpenRecall
binary.

Applying optimizer parameters or learning steps changes future scheduling
decisions. Existing scheduled due dates are not silently rewritten by either
operation.

## Dependency and runtime baseline

The bundled runtime remains Node.js 24.18.0 with pnpm 11.17.0 for source builds.
The reviewed refresh includes Fastify 5.11.3, `@fastify/sse` 0.6.0, Vite 8.2.1,
TypeBox 1.3.12, better-sqlite3 13.0.3, tsx 4.23.12, esbuild 0.28.2,
Rolldown and its native bindings 1.2.3, Playwright 1.62.1, axe-core 4.13.0,
and related React/testing patch releases.
Node 26 type definitions are intentionally excluded while the supported runtime
is Node 24.

Scheduling remains FSRS-6 through `ts-fsrs@5.4.1`; this release does not claim
FSRS-7 support.

## Verify the download

Compare the archive with
`OpenRecall-v1.1.0-windows-x64.zip.sha256`. With GitHub CLI installed, verify
the build provenance as well:

```bash
gh attestation verify OpenRecall-v1.1.0-windows-x64.zip -R aim9sour/OpenRecall
```

The release workflow builds the ZIP on Windows, runs normal and portable smoke
tests, publishes the SHA-256 file, and attests the ZIP before the draft release
is made public.

## Known limitations

- FSRS-7 is unsupported.
- There are no accounts, cloud sync, collaboration, rich media, Anki package
  import/export, or native desktop/mobile wrapper.
- The Windows ZIP is not code-signed. Verify its SHA-256 and GitHub provenance.
- Normal and portable databases are intentionally separate and are never
  merged or moved automatically.

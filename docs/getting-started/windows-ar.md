# تشغيل OpenRecall على Windows

OpenRecall تطبيق شخصي محلي يستمع فقط على `127.0.0.1`، ولا يحتاج إلى حساب أو
خدمة سحابية.

## الطريقة الموصى بها: حزمة الإصدار

1. افتح [أحدث إصدار](https://github.com/aim9sour/OpenRecall/releases/latest).
2. نزّل `OpenRecall-v1.0.0-windows-x64.zip` وفك الملف كله في مجلد تستطيع
   الكتابة فيه. لا تشغّل الملفات من معاينة الملف المضغوط.
3. انقر نقرًا مزدوجًا على أحد الملفين:
   - `OpenRecall.cmd` للوضع العادي.
   - `OpenRecall-Portable.cmd` للوضع المحمول.

تحتوي الحزمة على Node.js متحققًا منه، لذلك لا يحتاج مستخدم الإصدار إلى تثبيت
Node أو pnpm أو الاعتماديات أو أي خدمة. لا يطلب الملفان صلاحيات المسؤول ولا
ينزّلان شيئًا.

يفتح Chrome على `http://127.0.0.1:3210` إن كان متاحًا، وإلا يفتح Windows
المتصفح الافتراضي. إذا كان برنامج آخر يستخدم المنفذ 3210، يظهر
`OPENRECALL_PORT_OCCUPIED` بدل اختيار منفذ مفاجئ.

## اختر وضع البيانات

يحفظ الوضع العادي كل شيء داخل:

`%LOCALAPPDATA%\OpenRecall-nodejs\Data`

أما الوضع المحمول فيحفظ كل شيء داخل `Data` بجوار
`OpenRecall-Portable.cmd`. يجب أن يظل المجلد المفكوك قابلًا للكتابة. يؤدي نقل
المجلد أو نسخه إلى نقل أو نسخ قاعدة الوضع المحمول ونسخه الاحتياطية معه.

الوضعان معزولان: لا ينسخ OpenRecall البيانات بينهما ولا يدمجها ولا يرحّلها.
استخدم ملف التشغيل نفسه دائمًا إلا إذا كنت تريد مكتبة منفصلة عمدًا؛ لذلك قد
يبدو التطبيق فارغًا عند تبديل الملف رغم أن القاعدة الأخرى سليمة.

## الإغلاق الآمن

اترك نافذة الأوامر مفتوحة أثناء التشغيل. اضغط `Ctrl+C` فيها وانتظر حتى تغلق.
عندها تكتمل الطلبات الجارية وتتوقف أحداث المراجعة والمؤقتات ويُنفذ checkpoint
وتغلق SQLite بأمان. شغّل الملف نفسه لاحقًا للمتابعة.

## النسخ الاحتياطي ونقل البيانات

أنشئ ونزّل نسخة SQLite من الإعدادات قبل أي تغيير خطر. لا تنسخ ملف
`openrecall.sqlite3` الحي وحده أثناء عمل الخادم. أوقف التطبيق قبل نقل مجلد
الوضع المحمول أو نسخه. في الوضع العادي استخدم النسخة من داخل التطبيق بدل نقل
Local App Data يدويًا.

توجد اللقطات المتحقق منها داخل `Data\backups`، والسجلات الخالية من المحتوى
داخل `Data\logs`. قد تحتوي نسخة كاملة قديمة على بطاقات حُذفت نهائيًا لاحقًا.

## حل المشكلات

- `OPENRECALL_PORT_OCCUPIED`: أغلق البرنامج الذي يستخدم المنفذ 3210 ثم أعد
  المحاولة.
- `OPENRECALL_PORTABLE_DIRECTORY_NOT_WRITABLE`: فك الملف كله أو انقله إلى
  مجلد يستطيع حسابك إنشاء الملفات فيه.
- `OPENRECALL_LAUNCHER_FILES_MISSING`: فك الحزمة كاملة من جديد، ولا تنقل ملف
  CMD وحده.
- صفحة تعذر الاتصال: تأكد أن نافذة الأوامر مفتوحة، وشغّل الملف نفسه، وانتظر
  `OPENRECALL_READY` ثم فعّل إعادة المحاولة.

شارك كود التشخيص الظاهر فقط عند طلب المساعدة؛ لا حاجة إلى مشاركة بطاقات أو
قاعدة SQLite أو أي محتوى خاص.

## البناء من المصدر بدلًا من ذلك

يحتاج المساهمون إلى Node.js 24.18.x وpnpm 11.17.0:

```powershell
pnpm install --frozen-lockfile
pnpm build
pnpm start
```

انتظر `OPENRECALL_READY` ثم افتح `http://127.0.0.1:3210`. ملف المصدر
`scripts\start-openrecall.cmd` يتحقق من النسخ، وهو منفصل عن ملف التشغيل
المكتفي ذاتيًا داخل حزمة الإصدار.

## تثبيت PWA اختياري في Chrome

يستطيع Chrome تثبيت الصفحة المفتوحة كنافذة PWA. التخزين دون اتصال خاص بغلاف
التطبيق فقط، ولا يشمل ردود API أو نصوص البطاقات. يحتاج التحديث إلى إجراء صريح
ولا يعيد تحميل جلسة مراجعة نشطة تلقائيًا.

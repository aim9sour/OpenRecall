# OpenRecall support

## Usage questions

Use [GitHub Discussions](https://github.com/aim9sour/OpenRecall/discussions) for
installation help, JSON format questions, scheduler explanations, and ideas that
are not yet concrete bug reports. Describe examples with synthetic cards only.

## Reproducible defects

Use the repository's structured issue forms for bugs, accessibility problems,
and feature requests. Search existing issues first, identify the exact
OpenRecall, operating-system, Chrome, and assistive-technology versions, and
provide the smallest synthetic reproduction.

Never upload a real OpenRecall SQLite database, backup, card text, browser
profile, trace, log, secret, username, or absolute machine path. Maintainers may
close reports that expose private data and ask for a sanitized reproduction.

## Security vulnerabilities

Use [GitHub private vulnerability reporting](https://github.com/aim9sour/OpenRecall/security/advisories/new).
Do not open a public issue for an unpatched vulnerability. Follow the complete
process in [SECURITY.md](SECURITY.md).
